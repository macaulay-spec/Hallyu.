What "done" means (§45, in my own words)

A feature is done when all 12 hold, verified end-to-end against the real Supabase backend: UI matching the approved mockup · real tables/migrations · RLS tested both ways (allowed works, forbidden refused) · server-side logic where correctness/secrecy demands it · deliberate loading / error / empty states · analytics events firing · accessibility addressed · security addressed (no secrets in bundle, no client-trusted privilege, rate limits) · real-device tests pass · and the full flow works from account A, is visible from account B, and is undoable. "A button that opens nothing is not a feature. A beautiful screen backed by fake JSON is not a production application." If any screen can't hit its mockup's bar in build, I flag it — I don't quietly ship flatter.

2 Architecture Plan

Full schema, RLS matrix, and all details in docs/02-architecture-plan.md. Stack per §29: Expo RN + TypeScript · Supabase (Postgres/Auth/Storage/Realtime/Edge Functions) · FCM/APNs via Expo · Sentry · EAS. Modular monolith — no Redis, no microservices (§30).

System shape

Expo RN app ──────────────── Supabase ────────────── external (server-side only)

 TanStack Query (server s.)  Realtime (narrow)      AI provider ← ai-moderation adapter

Client reads local Postgres only — no TMDB keys in the bundle, no live TMDB calls, works offline. Both external deps sit behind one adapter each (§54: missing credential = documented config, never fake success).

Security (RLS) — designed before client exposure (§25A)

  • Helper functions: is_platform_staff(), is_community_staff(cid), is_follower(a,b) — no policy ever checks is_verified as an authorization input (§26).
  • Feeds read through RPCs (fn_for_you, fn_following) so block relationships are applied deterministically (RLS can't express "visible unless we block each other" cleanly).
  • Spoilers are presentation, not deletion: content is always sent; the veil hides casual exposure and is always revealable. Withholding = moderation (is_hidden).
  • Privileged writes (verify, ban, platform remove, role changes) require the role at query time + always write audit_logs.

State & data fetching · TMDB · Notifications

State (no overlapping libraries, §29)

  • TanStack Query v5 — all server state; cursor-paginated infinite feeds (20/page); metadata staleTime 24h (it's synced, not live); social reads 30s + refetch-on-focus.
  • Zustand — UI slices only: feed segment, spoiler reveal set, composer draft, onboarding progress, followed/muted sets.
  • Supabase Realtime, deliberately narrow: in-app notifications + live episode-discussion mode only. Home feeds pull, not stream.
  • Optimistic: reactions, bookmarks, follows, comments, mark-watched — each with rollback + toast.

TMDB (A-8, verified current model)

  • API v4, application-level Bearer read token in Supabase secrets — client never sees it.
  • tmdb-sync Edge Function, 6h cron: discover KR TV (discover/on-the-air/upcoming, ko-KR) → per-drama details/seasons/credits/persons → upsert by tmdb_id; fingerprint skips unchanged; never deletes on absence.
  • Everything cached locally; images hotlink TMDB CDN (FastImage + blurhash, attribution in About) with Storage-rehost fallback built into the adapter.
  • No token in this env yet → full adapter ships + idempotent editorial seed; go-live = one config line.

Notifications (§18)

  • Critical: episode_release, reply, mention · Important: community announcement, actor update, official announcement · Optional: trending, recommendation, milestone (in-app only by default).
  • Fan-out filters per recipient: category prefs, per-drama settings, mutes, blocks, quiet hours (push deferred, in-app kept).
  • episode-releases cron (30 min) fires from synced air dates → deep link to the veiled episode page.
  • Every notification carries its deep link; cold-start taps queue until the session is ready.

3 Design System — "The Wave"

Full spec in docs/03-design-system.md. Original by design (§35): not Apple's look, Apple's level of craft. The brand is 한류 — the Korean Wave — and the only ornament in the system is a single sine-wave line: logo, dividers, progress, loading, empty states. Everything else is flat, dark, and quiet so drama imagery and fan text carry the energy.

Type · Space · Icons

Type

  • Inter (400–700) for UI; drama titles in 700 tight-tracked with the Korean title (한글) as a quiet sub-line — the Korean-inspired display treatment, used sparingly (§35A).
  • Scale: 11 caption · 13 small · 15 body · 17 strong · 20 title · 24 H2 · 30 H1 · 40 hero.
  • Voice: warm, fandom-fluent, plain. Never corporate. Empty states speak to the fan.

Space & grid

  • 4pt base: 4/8/12/16/24/32/48 · gutter 16 · card padding 16 (§35A) · feed gap 8 · sections 24.
  • The 2:3 law: K-drama posters are 2:3 everywhere — the system's distinctive rhythm. Post stills 4:5 or 16:9.
  • Thumb reach: primary actions in the bottom third or top-right 100pt; three permanent anchors (tab bar, composer, raised Create).

Icons & motion

  • 24px custom line icons, 1.8px stroke, rounded caps. Home tab = the wave; Create = raised gradient circle (the app's only shadowed element).
  • Verified = gradient wave seal (not a checkmark badge). Airing = coral dot, one calm pulse / 4s.
  • Motion: spring sheets, 180ms tab crossfade, 250ms pushes, follow ripple (a wave), spoiler blur 24→0 in 300ms, wave-draw loading. Reduced-motion collapses everything to 80ms fades.

Signature components

Post card (the workhorse, §51)

Avatar · @username · time … [drama chip] · ⋯
body text (15pt, expandable) → 4:5 image (spoiler-veiled when flagged) → [♥ 1,284] [💬 342] [↻ 96] [🔖]
The drama chip — a 16×24 2:3 thumbnail + "My Bias, My Boss · Ep 12" — is the system's signature affordance: how "a post about an episode knows which drama and episode it belongs to" (§36.6) becomes one component.

Spoiler veil (§9 — the signature interaction)

Media blurred 24pt + brand-grad veil 35% + centered pill "⚠ Spoiler · My Bias, My Boss · Episode 12 · Tap to reveal". Episode page adds a banner: "⚠ Spoilers for Episode 12 — you're through Episode 11" with Reveal for session / I watched Ep 12 ✓. Blurring is presentation, never deletion — always revealable.

States (§38 — deliberate, never blank)

  • Loading: skeleton cards with wave shimmer (1.2s).
  • Empty: wave-line illustration + voice + one action. Locked copy: "Your fandom is quiet here. Follow a few dramas or communities to get things moving." / "No matching dramas, actors, users, or communities found." / "You're caught up."
  • Error: broken wave + "Couldn't load this right now." + Retry.
  • Offline: "Offline — showing cached content" pill (no fake local writes).
